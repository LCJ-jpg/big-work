# 第二次作业 · 视觉目标管理与跟踪系统

创梦之翼视觉组 · 2026 招新培训

## 1. 项目目标

视觉系统需要在一帧图像中同时管理多个被检测到的目标。不同目标有不同的运动特点：

- 普通装甲：连续丢失 3 帧后判定跟踪失败，跟踪期间按 x/y 速度预测位置；
- 旋转装甲：除位置外还要维护角度，连续丢失 5 帧后判定失败，跟踪期间按 x/y 速度预测位置并预测角度；
- 目标管理器：逐帧接收检测结果，维护所有目标，处理非法帧与重新追踪。

作业要求综合使用：封装、继承、`std::vector`，以及多个类之间的协作。

## 4. 数据契约

全部类型位于 `namespace rm`。

### 4.1 具名常量类型

| 类型 | 值 | 含义 |
| --- | --- | --- |
| `TargetType` | `ARMOR` | 普通装甲 |
|  | `SPINNING` | 旋转装甲 |
| `TargetStatus` | `LOST` | 丢失 |
|  | `TRACK` | 正在跟踪 |

### 4.2 结构体字段

`Observation`、`InputFrame`、`TargetSnapshot`、`Result` 的字段定义与含义，请直接查阅 `include/data_types.hpp` 中的注释，本文不再重复。

### 4.3 关键语义

- `InputFrame.timestamp_ns` 是本帧观测时刻，单位纳秒；ROS 2 `builtin_interfaces/Time` 使用 `sec` + `nanosec`，这里用等价的纳秒整数。速度和预测按时间差计算，不按帧数；有效帧的时间戳必须严格大于最近成功帧，首帧没有上一帧时间差。
- 坐标单位统一为米（m），角度单位统一为度（°）；速度单位为 m/s，角速度单位为 °/s。
- `Result.frame_id` 是本帧输入帧号，被拒绝的帧也填本帧帧号；内部“最近一次成功处理的帧号”不更新。
- `Result.targets` 必须包含目标管理器持有的**所有**目标，而不只是本帧观测到的目标。
- `TargetSnapshot.velocity_x` / `velocity_y` 与 `predicted_x` / `predicted_y` 对普通、旋转装甲都有效；速度按观测时间差计算，`predicted_*` 是按当前帧时间间隔推算的下一帧位置，不覆盖当前 `x` / `y`；本帧未观测且仍为 `TRACK` 时，在上一帧预测值上继续累加。
- `TargetSnapshot.angle`、`angular_velocity`、`predicted_angle` 仅旋转装甲有效，普通装甲固定为 0；旋转装甲的 `predicted_angle` 在 `TRACK` 时按帧间隔和角速度更新。
- 进入 `LOST` 时 `x`、`y`、`angle`、`velocity_x`、`velocity_y`、`angular_velocity`、`predicted_x`、`predicted_y`、`predicted_angle` 全部清零。
- `TargetSnapshot.missed_count` 在 `TRACK` 期间表示连续未观测帧数；进入 `LOST` 后是否继续增加不作要求，由实现自行决定；重新观测到目标时必须清零。
- 被拒绝的帧要原样返回当前快照，保证状态没有被部分修改。
- `tracking_target_count` 与 `lost_target_count` 是快照计数，被拒绝的帧保持不变。
- `armor_target_count` 与 `spinning_target_count` 分别统计 `targets` 中 `ARMOR`、`SPINNING` 类型的当前目标数，包含已进入 `LOST` 的目标；被拒绝的帧同样保持不变。

## 5. 功能需求

### 5.1 目标与阈值

| 类型 | 丢失阈值 | 额外行为 |
| --- | --- | --- |
| 普通装甲 | 连续 3 帧未观测到 → `LOST` | 按 x/y 速度预测位置；无角度预测 |
| 旋转装甲 | 连续 5 帧未观测到 → `LOST` | 按 x/y 速度预测位置；`TRACK` 时按角速度预测角度 |

- 记当前帧时间戳为 `t_ns`，上一成功帧为 `t_prev_ns`，帧间隔 `dt = (t_ns - t_prev_ns) / 1e9` 秒；目标距上次观测的时间差为 `dt_obs = (t_ns - 上次观测时间戳) / 1e9` 秒。首帧的 `dt` 取 0。
- x/y 速度 = （本次坐标 − 上次观测坐标）/ `dt_obs`，单位 m/s；角速度 = （本次角度 − 上次角度）/ `dt_obs`，单位 °/s。`dt_obs` 必须大于 0。
- 坐标单位为 m，角度单位为度；不做单位换算。速度单位是 m/s，角速度单位是 °/s。
- 预测公式中的 `dt` 是当前成功帧的帧间隔，不是目标自己的 `dt_obs`。
- 本帧观测到 `TRACK` 目标时，按 `predicted_x = x + velocity_x * dt`、`predicted_y = y + velocity_y * dt` 计算；本帧未观测且仍为 `TRACK` 时，在上一帧预测值上继续累加：`predicted_x += velocity_x * dt`、`predicted_y += velocity_y * dt`，未观测期间速度保持最后一次观测值不变。预测值只写入 `predicted_*`，不覆盖当前 `x` / `y`。
- 旋转装甲在 `TRACK` 时：本帧观测到时，先用 `dt_obs` 更新 `angular_velocity`，再计算 `predicted_angle = angle + angular_velocity * dt`；本帧未观测到且仍为 `TRACK` 时，先执行 `angle += angular_velocity * dt`，再计算 `predicted_angle = angle + angular_velocity * dt`；达到丢失阈值的那一帧不再推进。进入 `LOST` 后停止位置和角度预测，并将 `x`、`y`、`angle`、`velocity_x`、`velocity_y`、`angular_velocity`、`predicted_x`、`predicted_y`、`predicted_angle` 全部清零。
- 从 `LOST` 重新追踪的第一帧，状态回到 `TRACK`，`missed_count` 清零，位置和角度更新，速度（x/y 与角度）清零（不按本次与上次观测的差值计算），`predicted_*` 等于当前观测值；之后按相邻观测的时间差更新。

### 5.2 整帧校验与目标创建

以下情况必须**整帧拒绝**，且不修改任何目标、不更新最近成功帧号和时间戳：

1. `frame_id` 不大于最近一次成功处理的帧号（包括相等）；
2. `timestamp_ns` 不大于最近一次成功处理的帧时间戳（包括相等）；
3. 观测中存在负数目标编号；
4. 同一帧内目标编号重复；
5. 观测类型与已创建目标的类型不一致：编号的类型在首次创建时确定，后续帧不得改变；类型决定丢失阈值和角度预测行为，例如 1 已按 `ARMOR` 创建，后续又被报成 `SPINNING`，应整帧拒绝。

开始时目标管理器内无目标。每帧通过整帧校验后，按第 6 节的顺序处理观测。

### 5.3 丢失与重新追踪

- `LOST` 目标不能从容器移除：测试帧 13 和 21 依赖目标在 `LOST` 后重新追踪。
- `LOST` 后 `missed_count` 是否继续递增由实现自行决定，不作为验收条件；目标重新被观测时清零。

## 6. 程序流程

程序的入口在 `src/main.cpp`：

```text
main()
  └── 创建 TargetManager
        └── for frame in testFrames()        // 28 帧
              └── result = node.onFrame(frame)
                    └── printResult(result)
```

`onFrame` 期望签名：

```cpp
rm::Result onFrame(const rm::InputFrame& frame);
```

一帧的推荐处理顺序：

1. 校验 `frame_id` 和 `timestamp_ns` 是否都严格大于最近成功帧；
2. 校验观测（负数、同帧重复、已创建目标的类型不一致）；
3. 任一项失败 → 构造 `accepted=false` 的 `Result`，返回未变化的快照；
4. 全部通过 → 更新最近成功帧号和帧时间戳；
5. 遍历观测：已创建目标更新位置和状态，`missed_count` 置 0；旋转装甲更新角度，普通装甲角度保持 0；若上一帧为 `TRACK`，按观测时间差更新 x/y 速度和 `angular_velocity`，再按当前帧间隔计算预测值；若上一帧为 `LOST`，按重新追踪处理，不做差值计算，速度置 0、`predicted_*` 取本次观测；此前未创建过的编号新增目标（状态 `TRACK`、`missed_count=0`，类型、位置取本帧观测，旋转装甲角度取观测、普通装甲角度为 0，x/y 速度与角速度均为 0，预测值等于观测值）；
6. 遍历本帧未被观测的目标：仍为 `TRACK` 的目标 `missed_count++`；未达到阈值时，`predicted_x` / `predicted_y` 和旋转装甲的 `angle` 按帧间隔继续推进；达到阈值则转为 `LOST` 并清零位置、角度、速度和预测值；已处于 `LOST` 的目标是否继续增加 `missed_count` 由实现自行决定；
7. 统计 `TRACK` / `LOST` 数量以及 `ARMOR` / `SPINNING` 类型数量，构造 `accepted=true` 的 `Result`。

## 8. 实现建议

### 8.1 类划分

| 类 | 职责 | 关系 |
| --- | --- | --- |
| 目标管理器（推荐命名 `TargetManager`） | 持有所有目标，实现 `onFrame`，负责校验、逐帧更新、统计 | 持有 `std::vector` |
| 跟踪基类（如 `TrackingBase`） | 保存编号、类型、位置、状态、角度、丢失次数、速度与预测值；提供公共辅助函数 | 被两个派生类继承 |
| 普通装甲类（如 `ArmorTarget`） | 3 帧丢失规则 | 继承跟踪基类 |
| 旋转装甲类（如 `SpinningTarget`） | 5 帧丢失规则 + 角速度与角度预测 | 继承跟踪基类 |

基类析构函数应为 `virtual`，否则通过基类指针销毁派生对象是未定义行为。

### 8.2 实现注意点

- 所有成员默认私有，通过函数访问；不要把状态暴露为 public。

## 9. 输出格式

`src/main.cpp` 中的 `printResult()` / `printTarget()` 定义了当前输出格式，同学们直接使用即可，无需修改：

```text
frame=<帧号> accepted=<true|false>
tracking_target_count=<n> lost_target_count=<n> armor_target_count=<n> spinning_target_count=<n>
id=<编号> type=<0|1> status=<0|1> position=(<x>,<y>|--,--) velocity=(<vx>,<vy>) predicted_position=(<px>,<py>|--,--) angle=<角度> angular_velocity=<角速度> predicted_angle=<下一帧预测角度> missed=<n>
```

- `type`：`0` = `ARMOR`，`1` = `SPINNING`；
- `status`：`0` = `LOST`，`1` = `TRACK`；
- 位置、速度、角度和预测值保留 2 位小数；位置和预测位置单位为 m，速度单位为 m/s，角度单位为 °，角速度单位为 °/s；
- 仅当状态为 `LOST` 且 `x == 0 && y == 0` 时位置打印为 `--,--`；
- `LOST` 时 `velocity_x` / `velocity_y` 为 0，`predicted_position` 打印为 `--,--`。

被拒绝的帧同样会打印 `targets`，用于核对“整帧拒绝后状态不变”。

### 附加一：LOST 目标超时删除

基础要求中 `LOST` 目标会一直保留。本附加项要求：

- 从目标进入 `LOST` 的那一帧开始计数，连续 10 帧仍为 `LOST` 时，将目标从容器中删除；
- 删除后当前目标对象数减一；之后再次观测到同一编号时，按新目标创建；
- 只在整帧校验通过后的逐帧处理中删除；被拒绝的帧不改变计数或容器；
- 本附加项与 5.3 的基础保留规则冲突，仅在启用时覆盖。

启用后，测试帧中的目标 2 在第 6 帧进入 `LOST`，第 15 帧处理完时达到连续 10 帧 `LOST` 并被删除；第 21 帧观测到的 2 将作为新目标创建，而不是重新追踪旧目标，相关验收预期需相应调整。

### 附加二：类型变化时重建目标

基础要求中，已创建目标的类型不一致会导致整帧拒绝。实现本附加项后：

- 输入类型与已有目标类型不同时，不拒绝本帧；
- 删除旧目标对象，按本帧观测创建新目标；
- 新目标使用本帧类型，状态设为 `TRACK`，`missed_count` 设为 0，位置和角度取本帧观测值，速度清零，预测值等于观测值；
- 丢失阈值和预测行为以新类型为准，当前目标对象数不变；
- 帧号回退、负数编号、同帧重复仍按基础要求整帧拒绝。

未实现本附加项时，保持基础行为：类型不一致整帧拒绝。启用本附加项后，基础测试帧中“帧 23 把 1 报成 `SPINNING`”不再被拒绝，而是删除并重建目标 1。该帧位于序列末尾，接受后没有后续帧，因此不会因“最近成功帧号”推进而使后半段全部回滚拒绝；对应验收预期只需调整帧 23 本身。

### 附加五：目标排序

增加对返回的 `Result` 中 `targets` 排序的功能，按以下优先级：

1. 按目标状态排序，`TRACK` 排在 `LOST` 前面；
2. 状态相同时，按目标到原点的距离升序；
3. 状态和距离都相同时，按目标编号升序。

距离按欧氏距离计算：`sqrt(dx^2 + dy^2)`；实现中只比较平方距离也可以，排序结果相同。
